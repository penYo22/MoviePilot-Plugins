# 115离线下载

> ⚠️ 本插件调用 115 离线下载及网盘接口，存在触发风控或账号限制的风险。建议使用小号或测试账号，后果自负。

用于在 MoviePilot 中提交 115 离线任务，并在任务完成后自动交给 MoviePilot 整理链识别、转移、刮削和入库。

## 功能

- 支持 MP 内置 115 授权提交离线任务。
- 支持手动 Cookie 提交和查询离线任务。
- 支持磁力、ed2k、115 分享链接批量提交。
- 支持下载目录、媒体库目录、失败目录配置。
- 支持自动轮询、完成后等待、失败重试、每轮任务上限和 API 间隔。
- 支持失败达到上限后将任务文件夹移动到失败目录。
- 支持整理成功后清理空源目录。
- 数据页支持浏览 115 目录并设置下载、媒体库、失败目录。

## 授权说明

### MP 115 授权

推荐模式。先在 MoviePilot 的 `设置 -> 存储 -> 115网盘` 完成登录，插件会复用系统内置的 115 存储能力。

自动整理依赖 MoviePilot 内置 115 存储读取远端文件，因此自动入库建议使用此模式。

### Cookie 模式

Cookie 模式可用于提交离线任务和查询任务列表。填写 115 网页 Cookie，例如：

```text
UID=xxx;CID=xxx;SEID=xxx
```

仅 Cookie 模式不等于 MoviePilot 已配置 115 存储；如果没有 MP 115 授权，插件无法把远端文件交给 MoviePilot 整理链读取。

## 关键配置

| 配置项 | 说明 |
| --- | --- |
| 自动整理 | 启用后注册定时服务，按轮询间隔检查离线任务 |
| 离线下载保存目录 | 115 网盘中的离线任务保存目录，如 `/待整理` |
| 媒体库存放路径 | 整理目标路径；留空则使用 MoviePilot 的目录规则 |
| 整理失败目录 | 失败达到重试上限后，将任务文件夹移动到此目录 |
| 整理方式 | 移动或复制 |
| 轮询间隔 | 建议不少于 5 分钟，降低接口压力 |
| API 间隔 | 每次 115 API 调用前等待的秒数，建议 1-3 秒 |
| 完成后等待轮数 | 任务显示完成后再等待几轮，避免 115 文件列表尚未刷新 |
| 整理失败重试次数 | 整理失败后重试上限 |
| 每轮最多处理任务 | 防止任务堆积时一次轮询拖太久 |
| 记录保留天数 | 自动清理插件任务记录；0 表示只按数量截断 |

## 工作流程

```text
填写链接 -> 保存配置 -> 提交 115 离线任务
                      -> 记录为下载中
定时轮询任务列表 -> status=2 -> 标记下载完成
下一轮或等待指定轮数后 -> TransferChain.manual_transfer()
整理成功 -> 标记整理完成，可清理空源目录
整理失败 -> 累计重试
达到重试上限 -> 标记处理完成，可移动到失败目录
```

## 性能与稳定性建议

- 轮询间隔不要太短，建议 5-15 分钟。
- API 间隔建议设置 1-3 秒。
- 任务很多时降低“每轮最多处理任务”，让插件分批处理。
- “完成后等待轮数”保留为 1 或更高，能减少 115 离线刚完成但文件列表未稳定导致的整理失败。
- 如果自动整理一直失败，先确认 MoviePilot 的 115 存储已经登录，并确认下载目录在 115 网盘中真实存在。

## 常见问题

### Cookie 模式为什么提交成功但不能自动入库？

Cookie 模式只负责 115 离线提交和任务列表查询。MoviePilot 整理链读取 `u115` 文件仍依赖系统内置 115 存储授权。请在 MoviePilot 存储设置中完成 115 登录。

### 为什么下载完成后不立刻整理？

插件默认等待 1 轮再整理，避免 115 接口先返回完成状态但目录文件列表还没刷新，导致误判失败。

### 失败目录移动不生效？

请确认已配置失败目录，并且该目录在 115 中存在或 MP 115 授权可自动创建目录。Cookie 模式下失败目录必须能通过 Cookie 客户端按路径找到。
