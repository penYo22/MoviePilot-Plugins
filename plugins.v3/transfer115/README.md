# 115离线下载

> ⚠️ 本插件调用 115 离线下载及网盘接口，存在触发风控或账号限制的风险。建议使用小号或测试账号，后果自负。

用于在 MoviePilot 中提交 115 离线任务，并在任务完成后自动交给 MoviePilot 整理链识别、转移、刮削和入库。V3 版本另外支持扫描 115 下载目录，生成识别后的名称预览，并在确认后批量修改远端文件和媒体目录名称。

## 功能

- 支持 MP 内置 115 授权提交离线任务。
- 支持手动 Cookie 提交和查询离线任务。
- 支持磁力、ed2k、115 分享链接批量提交。
- 支持下载目录、媒体库目录、失败目录配置。
- 支持自动轮询、完成后等待、失败重试、每轮任务上限和 API 间隔。
- 支持失败达到上限后将任务文件夹移动到失败目录。
- 支持整理成功后清理空源目录。
- 数据页支持浏览 115 目录并设置下载、媒体库、失败目录。
- 支持使用 MoviePilot V3 媒体识别链扫描下载目录。
- 支持先预览原名称和推荐名称，再确认批量修改 115 文件名称。
- 支持同步修改媒体目录；扫描计划 30 分钟后自动失效。
- 提供独立的“115文件管理器”侧栏页面，可逐个勾选文件或全选当前目录。
- 支持在样例文件名上直接用鼠标拖选分隔文字，按拆分片段组合新名称并即时测试。
- 测试只生成预览，不修改远端；确认后才执行改名，并检查文件不存在、同名冲突和计划过期。
- 改名成功后自动调用 MoviePilot 内置 TMDB 识别链，显示命中电影、电视剧或未命中。

## 授权说明

### MP 115 授权

推荐模式。先在 MoviePilot 的 `设置 -> 存储 -> 115网盘` 完成登录，插件会复用系统内置的 115 存储能力。

自动整理依赖 MoviePilot 内置 115 存储读取远端文件，因此自动入库建议使用此模式。

## 文件管理器改名

启用插件并完成 MoviePilot 内置 115 授权后，在左侧“115文件管理器”中使用：

1. 进入目标目录，在左侧勾选需要改名的文件，可使用“全选文件”。
2. 选择一个文件作为样例，在样例文件名中用鼠标拖选分隔文字，例如 `.-.` 或 ` - `，点击“以此拆分”。
3. 使用片段按钮或手动编辑命名模板，例如 `{2} - {1}`；扩展名默认自动保留。
4. 点击“测试”，确认列表中的原名称、拆分片段和新名称都正确后，再点击“确认改名”。

测试阶段不会修改 115 文件。改名计划有效期为 30 分钟，执行时会再次确认远端文件仍存在，并拒绝同目录下的重复目标名称。

### Cookie 模式

Cookie 模式可用于提交离线任务和查询任务列表。填写 115 网页 Cookie，例如：

```text
UID=xxx;CID=xxx;SEID=xxx
```

仅 Cookie 模式不等于 MoviePilot 已配置 115 存储；如果没有 MP 115 授权，插件无法把远端文件交给 MoviePilot 整理链读取。

## 关键配置

| 配置项 | 说明 |
| --- | --- |
| 自动整理 | 启用后注册定时服务，按轮询间隔检查离线任务 |
| 离线下载保存目录 | 115 网盘中的离线任务保存目录，如 `/待整理` |
| 媒体库存放路径 | 整理目标路径；留空则使用 MoviePilot 的目录规则 |
| 整理失败目录 | 失败达到重试上限后，将任务文件夹移动到此目录 |
| 整理方式 | 移动或复制 |
| 轮询间隔 | 建议不少于 5 分钟，降低接口压力 |
| API 间隔 | 每次 115 API 调用前等待的秒数，建议 1-3 秒 |
| 完成后等待轮数 | 任务显示完成后再等待几轮，避免 115 文件列表尚未刷新 |
| 整理失败重试次数 | 整理失败后重试上限 |
| 每轮最多处理任务 | 防止任务堆积时一次轮询拖太久 |
| 记录保留天数 | 自动清理插件任务记录；0 表示只按数量截断 |

## 工作流程

```text
填写链接 -> 保存配置 -> 提交 115 离线任务
                      -> 记录为下载中
定时轮询任务列表 -> status=2 -> 标记下载完成
下一轮或等待指定轮数后 -> TransferChain.manual_transfer()
整理成功 -> 标记整理完成，可清理空源目录
整理失败 -> 累计重试
达到重试上限 -> 标记处理完成，可移动到失败目录
```

## 性能与稳定性建议

- 轮询间隔不要太短，建议 5-15 分钟。
- API 间隔建议设置 1-3 秒。
- 任务很多时降低“每轮最多处理任务”，让插件分批处理。
- “完成后等待轮数”保留为 1 或更高，能减少 115 离线刚完成但文件列表未稳定导致的整理失败。
- 如果自动整理一直失败，先确认 MoviePilot 的 115 存储已经登录，并确认下载目录在 115 网盘中真实存在。

## 常见问题

### Cookie 模式为什么提交成功但不能自动入库？

Cookie 模式只负责 115 离线提交和任务列表查询。MoviePilot 整理链读取 `u115` 文件仍依赖系统内置 115 存储授权。请在 MoviePilot 存储设置中完成 115 登录。

### 为什么下载完成后不立刻整理？

插件默认等待 1 轮再整理，避免 115 接口先返回完成状态但目录文件列表还没刷新，导致误判失败。

### 失败目录移动不生效？

请确认已配置失败目录，并且该目录在 115 中存在或 MP 115 授权可自动创建目录。Cookie 模式下失败目录必须能通过 Cookie 客户端按路径找到。

### 如何使用识别和批量改名？

1. 在插件设置中启用“识别改名”，并确认 MoviePilot 的 115 存储已授权。
2. 打开插件详情页，点击“生成改名预览”。插件会扫描下载目录中的视频文件，并调用 MoviePilot 当前媒体识别与命名规则。
3. 检查预览中的原名称和推荐名称，确认无误后点击“确认批量改名”。

识别失败、推荐名称重复、目录中识别到多个媒体或远端文件已变化的条目会被跳过，并在接口返回的 `errors` 或 `failed` 中列出。改名不会直接使用 Cookie 客户端执行，Cookie 模式仍只用于离线任务提交和任务查询；远端改名依赖 MoviePilot 内置 115 授权。

### 改名后 TMDB 复核显示什么？

点击确认改名后，插件会把改名后的完整文件名交给 MoviePilot 内置的“文件识别”入口（`MediaChain().recognize_by_path`），每个成功改名的媒体文件会显示：

- `电影`：TMDB 命中电影。
- `电视剧`：TMDB 命中电视剧；文件名可识别季集时会额外显示，例如 `第 1 季 · 第 3 集` 或 `第 1 季 · 第 3-5 集`。
- `未命中`：没有匹配到电影或电视剧，或识别链暂时不可用。

复核只负责反馈识别结果，不会因为 TMDB 暂时未命中而回滚 115 已完成的改名。
